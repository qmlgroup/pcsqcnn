# Article Artifact Contract

## Overview

This file defines the contract for the autogenerated article artifact pipeline.

- This document covers generated training artifacts, derived reevaluation payloads, per-task caches, and rendered PDFs.
- Download the paired source and data archives from the same
  [GitHub release](https://github.com/qmlgroup/pcsqcnn/releases).
- `pcsqcnn-source.zip` includes code and compact results; extract
  `pcsqcnn-plot-data.zip` at the resulting package root to create `artifacts/`.
- Together they supply every figure input and the final PCS weights needed
  for translation verification. Earlier artifact releases are not required.
- [REPRODUCING.md](REPRODUCING.md) gives the complete CPU plotting quick start,
  checksum verification and optional inference/training workflows.
- Rendered PDFs are produced in `figs/`.

The intended reading model is: if a script, payload, or PDF name appears here, downstream code may rely on the stated path, field names, and semantics as a contract.

## Shared conventions

### Directory roots

- Training data root: `data/`.
- Generated training and reevaluation artifacts root: `artifacts/`.
- Generated figure root: `figs/`.
- Article-facing copied figure root: `figs/`.

### Automated run directory contract

Every training family below is produced through `run_auto_training_manifest_tasks(...)` and therefore uses the same run-directory structure.

- Each run family uses an explicit `output.directory_name`, so article runs are not timestamped.
- Each run directory contains one `manifest.json` file, one `result_seed{seed}.pt` file per saved seed, one `checkpoint_final_seed{seed}.pt` per seed, and zero or more `checkpoint_epoch{epoch}_seed{seed}.pt` snapshot files.
- `manifest.json` top-level fields are:
  - `output_directory`: absolute path of the run directory.
  - `device`: resolved execution device used for training.
  - `resolved_config`: plain-data form of the global automated-training configuration.
  - `seeds`: ordered saved seed list.
  - `runs`: one per-seed entry.
- Each `manifest.json` run entry contains:
  - `seed`
  - `result`
  - `checkpoint_final`
  - `snapshots`
  - `final_train_summary`
  - `final_test_summary`
- The `seeds` list is the authoritative seed ordering. All figure loaders consume training histories in that order.
- Single-seed reevaluation scripts default to the first seed in `manifest.json` when `--seed` is not passed.

### Per-seed result payload contract

Each `result_seed{seed}.pt` payload stores the lightweight training summary for one seed.

- Top-level fields are:
  - `resolved_config`
  - `seed`
  - `device`
  - `loss_name`
  - `parameter_stats_line`
  - `final_summaries`
  - `training_history`
  - `collector_states`
  - `files`
- `files.result` repeats the result filename.
- `files.checkpoint_final` names the final checkpoint file for the same seed.
- `files.snapshots` maps saved epoch numbers, serialized as strings, to checkpoint filenames.
- `training_history` is the canonical source for train and test metric traces used by the translated-MNIST, brightness-sweep, architecture-sweep and image-size renderers.

### Figure aggregation conventions

- Numeric figures use the insertion widths and caption-size fonts defined in `qcnn.matplotlib_config`. The legacy `ARTICLE_PANEL_FIGSIZE=(6, 4)` is not the publication layout standard. Classical architecture schematics (Figure S2) use content-sized layouts.
- Figures 4 and 5 and the full-MNIST controls in Figure S3 pool accuracy values across three seeds within 50-epoch windows. Curves show pooled means; bands show the 25th-75th percentiles. The final test means shown as dots and horizontal guides in Figures 5 and S3 are computed separately from the final evaluation of each seed.
- The brightness sweep (Figure S1) shows the mean and min-max range across three seeds at each encoder setting, without temporal pooling.
- Gradient diagnostics (Figure 6) show means and interquartile ranges across 12 parameter initializations. Readout entropy (Figure S4) shows the mean and interquartile range across test images of one reference run, not across training seeds.
- FRQI comparison curves (Figure S10) and PCS readout curves (Figure S13) show unsmoothed means and sample-standard-deviation bands across three seeds, except sp-QCNN, for which two seeds are available. MFA curves (Figure S14) show three-seed means, with sample-standard-deviation bands on the test curves.
- `summarize_accuracy_histories(...)` retains its per-epoch population-SD convention for callers that use it; this does not describe the temporally pooled bands in Figures 4, 5 and S3.

Some training helpers retain `Figure2` in their API names. These identify the original translated-MNIST protocol; the manuscript places its comparison curves in Figure 5.

### Canonical reference run

The canonical full-MNIST reference run is the `16on16` member of the image-size sweep.

- Run directory: `artifacts/pcsqcnn_image_size_sweep/16on16`
- Dataset regime: full MNIST, `samples_per_class=None`
- Dataset geometry: `scaled_image_size=16`, `image_size=16`, `max_offset=0`
- PCS-QCNN architecture: `feature_qubits=3`, `quantum_layers=1`
- Encoder brightness range: `(0.0, pi)`
- Readout mode: full readout, not reduced-to-feature mode
- Training mode: exact-probability training and exact-probability checkpoints
- Dense snapshot schedule: `(10, 100, 200, ..., 2000)`

This run is the default upstream source for:

- `readout_entropy.pt`
- `finite_shot_accuracy.pt`
- `finite_shot_loss_sampling.pt`
- `readout_landscape.pt`
- `error_structure_seed{seed}.pt` when the default `16on16` size pair is used

## Published figure and table inputs

The plot scripts need only part of each artifact family: `manifest.json` and
the per-seed `result_seed*.pt` files of the runs they show, and the
evaluation payloads of the diagnostic figures. `run/export_plot_artifacts.py`
writes these files and the table-only comparator evidence to a separate folder, with the same relative
paths, keeping JSON files unchanged and replacing every `torch.save` file by
its JSON export with the same stem (`result_seed0.json` next to an unchanged
`manifest.json` that still names `result_seed0.pt`). The encoding of
`qcnn.json_artifacts` restores tensors with their dtype and shape and
dataclasses such as `TrainingHistory` exactly. The result and payload loaders
of the plot scripts (`qcnn.article_figures`, `qcnn.json_artifacts.load_payload`)
use the JSON export whenever the original file is absent. No figure reads a
model checkpoint, so the folder contains none; `INDEX.json` lists the files
every plot script reads. The runs in `EXTRA_RUN_DIRECTORIES` of the export
script are the untuned address-QCS runs `qcsqcnn_translated_mnist/fq2_ql3_sl1`
and `qcsqcnn_translated_mnist/fq2_ql3_sl8`, used in Supplementary Table S5.
They are exported the same way and listed under `runs` in `INDEX.json`.
The QCS validation-search record
`qcsqcnn_tuning/fq2_ql3_sl8/search_summary.json` is also included.
The sp-QCNN records are already selected by the common FRQI plotter.

- Stored contract:
  - Each run directory follows the shared automated run-directory layout.

- Downstream consumers:

  - `run/plot_classical_baseline_architectures.py` uses the same translated-MNIST model specs, but does not read the saved training artifacts

### Translated-MNIST QCS-QCNN controls

- Purpose: Stores the address-encoding QCS-QCNN controls (article Fig. 1(a,c)) used for the PCS-versus-QCS comparison on the translated-MNIST benchmark of Fig. 2.
- Producer script: `run/prepare_qcsqcnn_translated_mnist_data.py`
- On-disk location and filename contract:
  - Root directory: `artifacts/qcsqcnn_translated_mnist/`
  - Run subdirectory format: `fq{feature_qubits}_ql{quantum_layers}_sl{sublayers}`
  - Default run directories:
    - `fq2_ql3_sl1`: head-matched control
    - `fq2_ql3_sl8`: quantum core and head matched to the PCS-QCNN
- Upstream inputs and source data:
  - MNIST train/test data reconstructed under `data/`
  - Balanced translated-MNIST preprocessing with the same regime and seeds as the fixed translated-MNIST baseline runs
- Exact current defaults from code:
  - the translated-MNIST baseline dataset, optimizer, epoch, batch-size, and seed settings (`samples_per_class=1000`, `image_size=32`, `scaled_image_size=16`, `max_offset=8`, `train_batch_size=256`, `test_batch_size=1600`, `num_epochs=2000`, `seed_count=3`, `learning_rate=3e-2`)
  - Model spec:
    - `QCSQCNN(image_size=32, num_classes=10, feature_qubits=2, quantum_layers=3, sublayers=K, brightness_range=(0.0, pi), shot_budget=None, generator_init_scale=2*pi)`
- Stored contract:
  - Each run directory follows the shared automated run-directory layout.
  - `parameter_stats_line` counts the `QCSIndexLayer2D` modules as quantum: `q512 q2048 q2048 c2570 Q4608 C2570` for `sl1` and `q4096 q16384 q16384 c2570 Q36864 C2570` for `sl8`.
- Computation contract:
  - Encoder, pooling, conditioning, readout, and head are those of `PCSQCNN`.
  - Each layer applies `K` sublayers of `exp(i sum_j tau_j(h))` on the active x register with the feature register and then on the active y register with the feature register, with one shared local term per branch, sublayer, and axis on cyclic neighbouring index-qubit pairs.
  - Training and evaluation use exact infinite-shot probabilities.
- Downstream consumers:
  - `run/plot_qcsqcnn_comparison.py`

### QCS-QCNN learning-rate and initialization search

- Purpose: Selects the learning rate and initialization scale of the fully matched QCS-QCNN (`K = 8`) on a validation split, because the shared translated-MNIST hyperparameters leave it untrainable.
- Producer script: `run/tune_qcsqcnn_translated_mnist.py`
- On-disk location and filename contract:
  - Root directory: `artifacts/qcsqcnn_tuning/fq2_ql3_sl8/`
  - `states/lr{learning_rate}_init{init_scale}.pt`: model, optimizer, data-order generator state, history, and completed epochs of one setting
  - `search_summary.json`: written last; marks the search as complete
- Exact current defaults from code:
  - seed-0 translated-MNIST training set split by `stratified_validation_split` into 900 training and 100 validation images per class
  - grid: learning rate `{1e-3, 3e-3, 1e-2, 3e-2}` times initialization scale `{0.05, 0.5, 2*pi}`
  - successive halving: all 12 settings to 300 epochs, the best 4 to 1000, the best 2 to 2000
  - ranking: mean validation accuracy of the last 5 evaluations (every 10 epochs) at each rung
- Stored contract:
  - `search_summary.json` holds the grid, the rung schedule, every rung's ranking and scores, the selected setting, and each setting's per-evaluation validation history
  - the test split is never evaluated
- Downstream consumers:
  - `run/prepare_qcsqcnn_translated_mnist_data.py --learning-rate ... --generator-init-scale ... --root-directory qcsqcnn_translated_mnist_tuned`, which writes the tuned final runs to `artifacts/qcsqcnn_translated_mnist_tuned/fq2_ql3_sl8/` with the shared run-directory layout
  - `run/plot_qcsqcnn_comparison.py` (`qcsqcnn_tuning_curves.pdf`, tuned series in the QCS panels and table)

## Derived evaluation payloads

### `gradient_norms.pt`

- Purpose: Stores the depth-scaling initialization-time quantum-gradient diagnostics used for Figure 6: the norm of the empirical-loss gradient and the RMS norm of per-sample gradients.
- Producer script: `run/evaluate_gradient_norms.py`
- On-disk location and filename contract:
  - Assembled payload path: `artifacts/depth_scaling_gradient_norms/gradient_norms.pt`
  - Per-task cache root: `artifacts/depth_scaling_gradient_norms/`
  - Per-task directory: `depth{depth:02d}_pseed{param_seed:02d}/`
  - Per-task files: `manifest.json` and `result.pt`
- Upstream inputs and source data:
  - Freshly instantiated random-initialization PCS-QCNN models
  - Deterministically prepared balanced-subset MNIST test samples at the depth-dependent image sizes
- Exact current defaults from code:
  - `depths=(1, 2, 3, 4, 5, 6, 7)`
  - `param_seeds=(0, 1, ..., 11)`
  - `data_seed=0`
  - `post_pooling_index_qubits=1`
  - `feature_qubits=3`
  - `num_test_samples=256`
  - `class_balanced_subset=True`
  - `task_type="depth_scaling_gradient_norms"`
  - `format_version=5`
  - Local safety guard:
    - `LOCAL_SAFE_MAX_IMAGE_SIZE=256`
    - `LOCAL_SAFE_MAX_PARAM_SEED_COUNT=12`
    - `LOCAL_SAFE_MAX_NUM_TEST_SAMPLES=256`
    - `LOCAL_SAFE_MAX_TOTAL_WORK=3072`
- Stored contract:
  - Top-level payload fields:
    - `depths`
    - `param_seeds`
    - `data_seed`
    - `post_pooling_index_qubits`
    - `feature_qubits`
    - `num_test_samples`
    - `class_balanced_subset`
    - `evaluations`
  - Each `evaluations` entry contains:
    - `param_seed`
    - `depth`
    - `image_size`
    - `layer_keys`
    - `layer_labels`
    - `full_quantum_gradient_norm`: scalar tensor for the empirical-loss gradient over all quantum parameters
    - `first_quantum_layer_gradient_norm`: scalar tensor for the empirical-loss gradient in the first quantum layer
    - `last_quantum_layer_gradient_norm`: scalar tensor for the empirical-loss gradient in the last quantum layer
    - `quantum_layer_gradient_norms`: length-`depth` tensor of empirical-loss gradient norms for all quantum layers
    - `full_quantum_gradient_rms`: scalar tensor for the per-sample RMS gradient over all quantum parameters
    - `first_quantum_layer_gradient_rms`: scalar tensor for the per-sample RMS gradient in the first quantum layer
    - `last_quantum_layer_gradient_rms`: scalar tensor for the per-sample RMS gradient in the last quantum layer
    - `quantum_layer_gradient_rms`: length-`depth` tensor of per-sample RMS gradient norms for all quantum layers
  - Each task-cache manifest contains:
    - `task_type`
    - `format_version`
    - `saved_at_utc`
    - `param_seed`
    - `depth`
    - `image_size`
    - `scaled_image_size`
    - `max_offset`
    - `post_pooling_index_qubits`
    - `feature_qubits`
    - `num_classes`
    - `data_seed`
    - `num_test_samples`
    - `class_balanced_subset`
    - `result_filename`
- Computation contract:
  - For each depth/parameter-seed pair, the evaluator instantiates a fresh PCS-QCNN in the depth-scaling regime with `image_size = 2^(post_pooling_index_qubits + depth - 1)`.
  - The script selects one deterministic class-balanced test subset using `data_seed`, preprocesses it at the depth-dependent image size, and accumulates both microbatch gradient sums and squared per-sample gradient norms.
  - Per-sample gradients are evaluated once with `torch.func.functional_call`, `torch.func.grad`, and `torch.func.vmap`, then reduced microbatch-by-microbatch to avoid storing the full Jacobian.
  - The adaptive microbatch fallback halves the current batch size after CUDA OOM until it reaches `1`; if that still fails, the script raises instead of writing a partial task result.
- Downstream consumers:
  - `run/plot_gradient_norms.py`
  - Rendered PDF:
    - `gradient_norms.pdf`

### `readout_landscape.pt`

- Purpose: Stores loss landscapes in sample-local shot-noise coordinates for the canonical reference run (seed 0).
- Producer script: `run/evaluate_readout_landscape.py`
- Locations:
  - Assembled payload: `artifacts/pcsqcnn_image_size_sweep/16on16/readout_landscape.pt`
  - Per-epoch cache: `artifacts/pcsqcnn_image_size_sweep/16on16/readout_landscape/epoch{epoch:03d}/`, with `manifest.json` and `result.pt`
- Inputs: the canonical `16on16` checkpoints and their reconstructed MNIST test split.
- Current evaluator defaults:
  - `epochs=(10, 100, 800)`; Figure S5 uses epochs 100 and 800
  - `alpha_beta_points=81`, `axis_limit=3.0`
  - `sample_batch_size=128`, `grid_chunk_size=512`
  - `sigma_shot_budget=128`
  - `basis_mode="sample_local_pca_exact_readout_shot_noise_covariance"`
  - `task_type="readout_landscape"`, `format_version=6`
- Stored contract:
  - Top-level fields: `seed`, `epochs`, `pc1_sigma`, `pc2_sigma`, `sigma_shot_budget`, `basis_mode`, `total_samples`, `evaluations`.
  - Each evaluation stores `epoch`, `mean_loss`, `valid_count`, `valid_fraction` and `eligible_sample_count`. Grid tensors have shape `[len(pc2_sigma), len(pc1_sigma)]`.
  - Per-task manifests record the task/version, seed, epoch, grid and batching settings, shot budget, basis mode, total sample count, timestamp and result filename.
- Computation:
  - For each test image with exact readout `p`, form `(diag(p) - p p^T) / sigma_shot_budget` and take its two leading positive eigenmodes. The axes are local to each image, rather than eigenmodes of a test-averaged covariance. Each eigenvector is scaled by the square root of its eigenvalue and sign-canonicalized.
  - Add the two scaled directions to `p` at each grid point. Invalid perturbed distributions are excluded, not renormalized. The payload records their validity counts alongside the mean loss over valid samples.
- Consumer: `run/plot_readout_landscape.py`, which renders epochs 10, 100 and 800. Only `readout_landscape_epoch100.pdf` and `readout_landscape_epoch800.pdf` enter Figure S5.

    - predicted label in `midnightblue`
    - true label in `tab:blue`
  - If the payload contains zero misclassified samples, the panel shows `No misclassified samples`.

## Compact numerical bundles

`results/pcs_translation_2026-10-25/` contains portable training records,
cyclic-translation metrics and a run index with checkpoint hashes. Its
README gives the plotting and per-image verification commands.
`results/mfa_translated/` contains the MFA/PCS learning histories and metrics.
`results/figure1_crosses/` contains the Figure 1 state arrays and symmetry checks.
Each bundle describes its own numerical protocol; checkpoints are stored
separately under `artifacts/`.

The data archive includes `artifacts/pcs_translation_weights/INDEX.json` and
twelve final inference checkpoints. Each checkpoint contains only the model
specification and tensors. The index records its checksum and the original
training-checkpoint hash. `run/verify_pcs_translation.py` regenerates the large
per-image arrays into `artifacts/pcs_translation_recomputed/` as needed and
checks every map statistic against the compact reference results. These caches
are excluded from publication archives.
